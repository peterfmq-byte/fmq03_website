01 — 关于我

喜欢把东西拆开，搞清楚它为什么这样工作

喜欢把一个东西拆开，搞清楚它为什么这样工作，然后再想想能不能自己搭一个的人。

从一条网络连接是怎么建立的，到一个 CPU 的访存请求怎么一路走到内存；从 FPGA 上的数据链路， 到 Chiplet 之间怎样通信；甚至买了一副耳机之后，我也可能顺手去研究一下它的佩戴检测、双耳同步和充电盒到底是怎么工作的。

所以我的兴趣范围看起来经常有一点……发散。但它们其实都围绕着同一件事情： 系统是怎样被搭起来的？

02 — 研究

我主要在研究什么

专业兴趣主要集中在数字硬件和计算机系统。相比只关注单个模块， 我对 “一个完整系统里的不同部分如何连接起来” 更感兴趣。

数字 IC 设计与实现·Chiplet 与片间互联· SoC 与计算机体系结构·FPGA· Memory System·NoC / D2D / UCIe· RTL 设计与验证·数字后端设计· 系统级仿真·硬件建模与设计空间探索· 数字 IC 设计与实现·Chiplet 与片间互联· SoC 与计算机体系结构·FPGA· Memory System·NoC / D2D / UCIe· RTL 设计与验证·数字后端设计· 系统级仿真·硬件建模与设计空间探索·

真正让我感兴趣的，往往是：它们放到一起之后会发生什么？

Q1

带宽够不够？

当计算、存储与互联被放进同一个系统，瓶颈会出现在哪里。

Q2

延迟从哪里产生？

从一次访存到一次跨 Die 通信，延迟究竟在哪些环节被叠加。

Q3

协议之间怎样转换？

NoC、D2D、UCIe……不同层次互联协议如何彼此衔接。

Q4

RTL、模型与真实芯片

同一个设计在架构模型、RTL 和真实芯片之间分别意味着什么。

04 — 工程方式

把猜测变成证据

遇到一个陌生概念时，我一般不会满足于一句定义，而是会继续往下问：

  • 它为什么存在？
  • 如果没有它会怎样？
  • 真实系统里是谁在做这件事？
  • 它最终对应到硬件上是什么结构？
  • 能不能做一个最小版本验证一下？

有时候本来只是想解决一个五分钟的问题，最后却打开了二十个网页、三个 GitHub 仓库和两篇论文， 然后几个小时过去了。至少问题通常是搞明白了。:)
